# 翠湖花园社区 · 时间银行与银龄守护互助平台（Web 版）

> 把「小程序版社区互助」搬进浏览器：求助发单 → 就近接单 → 上门签到 → 双向确认 → 时间币结算，
> 全流程可交互演示，并按受控社区（路线 B）的合规口径实现「先审后发、实名准入、敏感信息分级脱敏」。

本仓库在 `433525/community-service-mvp`（Vue 3 演练原型）的调研结论之上继续开发，
将其中验证过的工程基线——**全局 Toast、弹层焦点管理、内容预检、发布草稿、容错存档读取**——
迁移到 React + TypeScript + Tailwind CSS 的产品级实现中。
当参考实现与《社区服务网页版开发步骤与雷点》《社区服务小程序功能说明》存在分歧时，**以文档为准**。

## 一、两种体验形态

| 形态 | 说明 |
| --- | --- |
| 宽屏网页端 | 自适应 320px ~ 1440px+，顶部导航 + 主内容 + 合规页脚 |
| 小程序模拟器 | iPhone 16 Pro 视口机身框、灵动岛与状态栏，还原微信小程序底部五栏结构 |

右上角可一键切换，底部五栏为：**首页 / 社区 / ＋发布（中央凸起）/ 消息 / 我的**。

## 二、功能矩阵

**首页**
- 全局搜索（服务类型 / 志愿者 / 求助单 / 养老科普，`⌘K` / `Ctrl+K` 快捷唤起）
- 轮播 Banner（时间银行规则、志愿招募、养老科普周）
- 六大便民入口：我要求助、我要接单、**紧急求助 SOS**、养老科普、志愿证明、帮助中心
- 附近可接单志愿者（距离 / 技能 / 评分）、热门急需求助订单

**社区**
- 置顶公告（原地展开，不打断阅读）、月度时间币英雄榜 TOP5
- 分类标签（志愿风采 / 线下活动 / 闲置互助 / 求助交流）+ 本社区 / 官方筛选
- 动态卡片：点赞、评论、收藏、复制链接转发、活动报名、闲置借赠标识
- 社区互助微信群入口（二维码 + 客服拉群兜底）

**＋ 发布**
- 发布求助订单（长者 / 家属代办）：类型、描述、时间、时长、门牌分级、病史单独授权、加急
- 发布志愿风采（可前台匿名，后台实名绑定）
- 普通邻里贴 / 闲置互助（0 时间币纯公益）
- **内容安全预检**（违规词阻断 / 风险词提醒）与**草稿自动暂存**（合规勾选不恢复）

**消息**
- 订单进度、订单内留言（文字 / 快捷语 / 位置卡片 / 照片）、官方通知、投诉反馈工单

**我的**
- 时间银行资产卡、不可篡改双向流水账本（幂等流水号）
- 订单状态机：认领 → 签到 → 完成结算 → 五星评价
- 志愿服务电子证明（防伪编号 / 核验二维码 / 打印存 PDF）
- 适老化大字模式、帮助中心语音教程、社区网格管理与风控后台

## 三、设计系统

- **色彩**：翡翠绿 `#059669 / #0d9488`（社区守护）＋ 琥珀 `#f59e0b`（时间币）＋ 暖灰中性底 `#f1f5f9`，深色仅用于页脚与机身框。
- **字体**：Noto Sans SC（界面）＋ Noto Serif SC（证书 / 展示），中文可读性优先，正文最小 14px。
- **Token**（`src/index.css`）：`--text-body / --text-title / --text-small / --tap-min / --focus-ring / --radius-card / --ease-out`。
- **动效原则**：动效为功能服务——确认操作、提示状态变化、引导视线；全部动效遵循 `prefers-reduced-motion`。
- **无障碍**：跳过链接、焦点可见实色描边、弹层焦点进入/循环/归还、`aria-live` 分级播报、触控热区 ≥ 44px、表单控件 16px 防 iOS 缩放。

## 四、技术栈与结构

```
src/
├─ App.tsx                 应用外壳：双视口、错误边界、全局快捷键、弹层调度
├─ components/             19 个业务与基础组件（含 BrandMark / SmartImage / ErrorBoundary）
├─ context/AppContext.tsx  全局状态：身份、订单状态机、时间币账本、消息、投诉
├─ data/mockData.ts        合成数据（本机演示数据，非真实居民信息）
├─ hooks/useDialog.ts      弹层可访问性基线
├─ types/index.ts          领域类型定义
└─ utils/                  audio（语音/音效）、storage（容错存档）、moderation（内容预检）、draft（草稿）、toast
```

技术栈：React 19 · TypeScript · Vite 7 · Tailwind CSS 4 · lucide-react · canvas-confetti。
构建为单文件产物（`vite-plugin-singlefile`），便于任意静态托管。

## 六、兼容性与性能

- 兼容 Chrome / Edge / Safari / Firefox 近两年版本；移动端优先适配 320–430px，桌面端居中容器。
- 图片统一懒加载与异步解码，加载失败退化为品牌占位块，不出现破图。
- 本地存档带版本信封与结构校验，单条损坏自动回退默认数据，**不会因脏数据白屏**。
- 写入失败（隐私模式 / 配额满）静默降级，不影响主流程。

## 七、合规要点（对应《开发步骤与雷点》）

| 雷点 | 本实现的做法 |
| --- | --- |
| R2 个人主体开放 UGC | 采用「受控社区」路线 B：先审后发 + 实名准入 + 订单内留言（不开放陌生人私信） |
| R5 未实名发布求助 | 发布求助前置实名校验，未认证跳转认证弹层 |
| R6 敏感个人信息 | 门牌分级脱敏（公开仅到小区/期数）、病史单独勾选授权、接单后凭证可见 |
| R7 无内容审核 | 本地敏感词预检（阻断/提醒分级）+ 管理后台审核队列与处置留痕 |
| R12 把紧急求助当急救通道 | SOS 弹层显著提示 120/110 优先，页脚重复免责声明 |
| R18 时间币可兑现 | 规则明确「仅记账、不可兑现、不可转让」，写入用户协议文案 |
| T5 底部导航被遮挡 | `env(safe-area-inset-bottom)` + 固定底栏安全区 |

> 说明：本项目为交互演示环境，全部数据为本机合成，不含真实个人信息，**不可用于真实运营**。
> 上线前仍需完成主体注册、ICP 备案、公安联网备案、内容审核值班与用户协议定稿。

## 八、与参考仓库的差异

| 维度 | `community-service-mvp`（Vue 3 演练原型） | 本仓库 |
| --- | --- | --- |
| 形态 | 双入口本机演练页 | 产品级双视口 Web 应用 |
| 数据 | 本地合成存档 | 同为本机合成，但带版本信封与容错读取 |
| 反馈 | 单条 toast | 分级播报 Toast（错误 `role=alert`） |
| 内容治理 | 审核日志 + 举报去重 | 预检拦截 + 审核队列 + 工单闭环 |
| 视觉 | Token 基线 | 完整品牌系统（矢量标识、字体、动效、质感） |
