# 社区服务双入口原型 · B 端受控社区 + A+ 受理工作台

> **仅合成数据演练。** 本仓库没有后端、没有真实账号、不发送任何通知、不采集真实居民信息，也不对外提供服务。
> 页面里的社区、居民、志愿者、订单、投诉、时间线全部由本机生成，清理浏览器数据即消失。

两个入口，一份领域层：

| 入口 | 地址 | 技术栈 | 是什么 |
|---|---|---|---|
| B 端受控社区 | `/`（`index.html`） | React 19 + Vite + Tailwind 4 | 居民视角：五栏导航、发布、先审后发、接单、留言、审核后台 |
| A+ 受理工作台 | `/aplus.html` | React 19 + Vite + mvp 原生 CSS | 内部视角：登记队列、分诊、检查点、高风险停止、投诉复核、备份 |

A+ 通过 `src/data/intake/community-bridge.ts` **只读** B 端的本机存档，把「审核通过的求助帖」登记成受理记录；不写回、不复制数据。

当本仓库实现与《社区服务小程序功能说明》《社区服务网页版开发步骤与雷点》（R1–R20 / T1–T20 / O1–O6）冲突时，**以文档为准**；232 原 UI 只决定外观，不决定功能范围。

## 一、快速开始

```bash
npm ci            # 或 npm install
npm run dev       # 开发：/ 与 /aplus.html
npm run build     # 生产：产出 dist/index.html 与 dist/aplus.html
npm run preview   # 预览：http://localhost:4173
```

验收（需先 build + preview 到 5180）：

```bash
npx vite preview --port 5180 --strictPort
npm run check:dual        # 27 项：双入口 + 五档宽度 + 弹层焦点
npm run check:aplus       # 24 项：A+ 主流程 + 去重 + 备份 + 持久化
npm run check:community   # 11 项：实名拦截 + 先审后发 + 跨入口读取
npm run check:acceptance  # 27 项：接单→签到→完成→账本、举报入口与处置、病史可见性、高风险拦截
npm run check:recovery    # 23 项：坏档恢复、跨标签冲突、评论级举报、官方措辞扫描
```

共 **112 项**，全部通过。脚本为零依赖 CDP 实现（Node 22 自带 WebSocket），会自行拉起
headless Chromium；详见 [验收记录](docs/delivery/acceptance.md)。

## 二、演示 vs 生产

这张表是本文档最重要的部分。左列是**现在能看到的**，右列是**要上线还缺的**。

| 能力 | 本仓库（演示） | 真实运营所需 |
|---|---|---|
| 账号与身份 | 浏览器内切换「访客 / 成员 / 审核员」三个演示身份，无登录 | 服务端会话、真实实名核验、社区成员准入、逐请求鉴权 |
| 内容审核 | 先审后发：发布写 `pending`，审核通过才进公开流 | 审核值班表、时限承诺、敏感词库、图片审核、申诉与复核 |
| 求助订单 | 本机状态机 + `orderEvents` 时间线，文案标注「本机演练」 | 真实派单、通知、履约凭证、并发控制、争议仲裁 |
| 时间币 | `unsettled` 只读流水，**不可兑现、不可转让** | 规则、双方确认、冲正、幂等业务号、审计与公示 |
| 消息 | 本机留言与系统通知列表，无投递 | 传输通道、未读校准、失败补偿、订阅消息分级 |
| 投诉 / 举报 | 两套独立的本机队列（举报=内容处置，投诉=复核演练） | 分派、时限、结果通知、归档与抽查 |
| 备份 | 手动导出 JSON；两端都能「下载坏档原文再重置」；A+ 另有导入（5 MB 上限） | 自动备份、异地多版本、恢复演练 |
| 急救 | 只提示「请手动拨打 120 / 110」，不做 `tel:` 链接，不定位不派单 | 明确的服务时间、响应机制与免责边界 |
| 合规页脚 | 声明「未办理 ICP / 公安联网备案」 | 主体、域名实名、ICP 备案、公安联网备案、日志留存 ≥ 6 个月 |
| 部署 | 纯静态产物，未绑定域名、未开 GitHub Pages | 境内合规云、HTTPS、监控、内容安全服务 |

## 三、功能范围

**B 端（`/`）**：五栏导航（首页 / 社区 / ＋发布 / 消息 / 我的，移动端固定底部）；首页搜索 + Banner 轮播 + 六个快捷入口 + 附近志愿者 + 热门求助；社区分类筛选、点赞/评论（可逐条举报）/收藏/转发、公告置顶、闲置互助；发布求助订单 / 志愿动态（可前台匿名）/ 邻里帖；消息四 Tab + 未读角标；我的六项（资料、实名档位、账本、证明、设置、管理入口）；管理侧审核队列、举报处置、投诉工单、操作日志、**存档与恢复**（六态存档状态、导出备份、载入存档、坏档取原文、重置门禁）；存档异常时主内容区顶部常驻警示条。

**A+ 端（`/aplus.html`）**：登记队列（7 种筛选 + 搜索）、详情（检查点、风险标记、关联记录、追加式时间线）、10 个弹层（新建 / 流转 / 检查点 / 跟进 / 模拟联系 / 高风险 / 重开 / 投诉 / 社区桥 / 使用说明）、4 张指标卡、投诉复核队列、备份与重置、深链 `?case=`。

五条状态机严格按文档实现：求助订单、志愿动态、邻里帖、投诉、审核。**唯一**的 schema 扩展是 `ORDER_EVENT_TYPES` 新增 `'clock-in'`（上门签到），用于补齐「接单 → 签到 → 完成」演示链路。

## 五、已知边界

- **只在 Chromium 验证**：未测 Firefox / Safari / 微信 X5（T3）。
- **A+ 未移植离线提示**：232 无 Service Worker，本轮不引入 PWA；mvp 的 `OfflineNotice` 因此省略。
- **备份「导入」的文件选择未自动化**：导出与刷新持久化已覆盖，导入靠手工走查。
- **A+ 全树重渲染**：`useSyncExternalStore` 订阅单一版本号，记录量上千时需改为按字段订阅。
- **B 端备份只有导出、没有导入**：导出、坏档取原文与重置门禁已具备；导入仍需手工操作存档键。
- **B 端坏档门禁在最外层是 UI 守卫**：绕过界面直接调用 `store.resetDemoData()` 仍可覆盖原文（领域层保留 `allowRecovery` 逃生口）。
- **举报目标是「帖子 / 评论 / 订单留言」三级**，但订单留言的举报入口尚未接到消息列表（领域已支持 `targetType: 'message'`）。
- 其它缺口逐条列在 [双向缺口报告](docs/delivery/gap-report.md)。

## 六、合规声明

1. **仅合成数据**：本仓库不包含任何真实居民、电话、身份证号、门牌号、病史或机构信息。所有示例人物与社区均为虚构。
2. **不冒充官方**：全站使用「项目组 / 互助演练」名义；未获得任何社区、街道或机构授权，不代表任何官方主体。
3. **不是急救通道**：紧急情况请直接拨打 120 / 110；本原型不定位、不通知、不派单。
4. **不收费**：没有支付、充值、兑换、佣金。
5. **不索引**：所有入口 `noindex,nofollow,noarchive`，并附 `robots.txt: Disallow: /`。
6. **素材**：图标为手写内联 SVG，头像为空串回退为 CSS 渐变占位，字体使用系统栈，**无任何外部 CDN 或第三方素材**。
