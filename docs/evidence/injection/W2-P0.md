## 二、观测到的关键细节

1. **第 1 组**：按钮解除禁用后，领域层仍以「请填写审核理由」拒绝写入，因此 `auditLog` 长度不变（`2→2`）。真正区分「UI 门禁失效」的是 `disabled=false` 与点击产生 toast 两项；这也说明该断言不能只验存档。
2. **第 2 组**：取消留痕（`p0#6`）与不结算（`p0#7`）在终态被改坏时**仍然通过**——证明三条断言彼此独立，不存在一条断言顺带覆盖另一语义的假象。
3. **第 3 组**：门禁移除后弹层直接关闭且身份切换成功，`p0#11`（正向切换）与 `p0#12`（刷新回落）不受影响，说明负向断言承担的是「拒绝路径」而非「成功路径」。

## 三、回滚校验

- 三处 `git checkout -- <file>` 后 `git status` 无 `src/` 变更。
- 回滚并重建后复跑：`check-p0-gaps` 恢复 12/12。
- 结论：三组 P0 断言具备缺陷判别力，可作为 W2 出口判据的证据。
