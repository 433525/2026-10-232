## 1. 问题陈述

契约层向外暴露了 `viewMode: 'mobile_frame' | 'responsive_web'` 与 `setViewMode`，但该字段自移植完成后从未被任何界面读取，也未写入任何验收断言。它带来三项可量化的代价：

1. **指标不可达**：可达性矩阵（M4）分母 53 条中含此 1 条 `unused`，使 100% 在结构上不可达，天花板被锁在 52/53 = 98.1%。
2. **类型面噪声**：`AppContextType` 是 24 处 `useApp()` 解构的唯一来源，多一个字段即多一处误导——读者会合理推断「存在移动框/自适应切换能力」，实际不存在。
3. **维护成本**：该字段带一条独立的 localStorage 键与一次 `safeRead`/`safeWrite` 往返，是存档容错链路上的一处无收益分支。

## 2. 证据（均可复现）

| 解构点 | `grep -rn "useApp()" src --include="*.tsx" \| wc -l` | 24 处，**无一处取用** `viewMode` / `setViewMode` |
| 断言引用 | `grep -rn "viewMode" tools/*.mjs \| wc -l` | **0** |
| 对照组（判据有效性） | `grep -rn "elderlyMode" src --include="*.tsx"`（排除定义文件） | **5 个文件 12 处**消费：`App.tsx:60,118`、`HeaderNav.tsx:32,122,125,130`、`EldercareModal.tsx:20,62,116`、`HelpCenterModal.tsx:60` 等 |

> 对照组的意义：判据若只是「关键词零命中」就判死，会把 `elderlyMode` 这类活字段一并误杀。`elderlyMode` 有真实消费方，`viewMode` 没有——这证明该判定区分的是「有无消费方」，而非「名字是否常见」。

## 3. 影响分析

| 维度 | 现状 | 删除后 | 判断 |
|---|---|---|---|
| 渲染与交互 | 默认值 `responsive_web` 从未被读取，无任何组件依赖 | 完全一致 | **零行为变化** |
| 布局断点 | 响应式由 CSS 断点（≥1200 / 1024–1199 / ≤1023）承担，与 `viewMode` 无关 | 不变 | 语义重复项消除 |
| 存储 | 键 `community.ui.view-mode` 可能已写入部分浏览器 | 成为孤儿键，不再读、不再写；不参与业务存档 `community-mvp.synthetic-state.v1`，不参与跨标签冲突检测 | 无需迁移；不清理亦无副作用 |
| 契约声明 | `AppContext.tsx:62-65` 明写「与 232 原实现完全一致的上下文契约（字段名与签名不变）」 | **该声明被打破**，必须同批改为「除 D-03 删除项外一致」 | 必须同批修订，否则形成新的文档—实现偏差 |
| M4 度量 | 53 条：covered 41 / gap 11 / unused 1 → 77.4% | 52 条：covered 41 / gap 11 / unused 0 → **78.8%** | 分母净化。**注意：被移除的是 `unused` 而非 `gap`，缺口仍为 11 条**，100% 仍须 W3–W5 逐批补齐 |
| 门禁耗时 | 223 条 / 418.9 s，指纹 `sha256:e9905d…` | 删除 `src/` 任一字节即令指纹失效（D-15），须整段重采 | 一次性约 7 分钟成本 |
| 断言总量 | 223 | 预期仍 223（无断言引用此字段） | 若变为 222 则说明存在隐藏引用，须回滚排查 |

## 4. 备选方案

| 方案 | 做法 | 收益 | 代价 | 结论 |
|---|---|---|---|---|
| **A 删除**（建议） | 删 10 处定义 + 改契约注释 | M4 天花板 100%；契约面收窄；去一次无收益存储往返 | 打破「逐字一致」声明，须 ADR + 注释修订；未来若真要做移动框预览需重建 | **建议采纳** |
| B 保留并补入口 | 新增「移动框 / 自适应」切换按钮，并加 1 条断言使其 `covered` | 保住契约一致性；M4 可到 53/53 | 为无人需要的开关造 UI，与响应式断点语义重复；+1 条断言与约 0.8 人日，挤占 W4 的 ADR 与四域设计预算 | 不采纳 |
| C 保留并标 `@deprecated` | 仅加注释，不删代码 | 零风险 | 字段仍在类型面与分母中，天花板维持 98.1%，与「指标须可达成」原则冲突；且 `noUnusedLocals` 管不到接口字段，无人会被编译器提醒 | 不采纳 |

**取舍说明**：A 的唯一实质代价是「契约逐字一致」这条自我约束。该约束的原意是防止移植时**丢失**既有能力；而 `viewMode` 从未产生能力，删除不构成能力丢失。故判定 A 优于 B、C。
