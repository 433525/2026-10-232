# P4 清理与验收 · 开源调研

调研日期：2026-10-23。目标：给出可复现的验收手段——五档宽度无横向溢出、弹层可访问、合规红线逐条留证。

## 候选

| # | 候选 | 许可 | 与本阶段的关系 |
|---|---|---|---|
| 1 | axe-core（Deque） | MPL-2.0 | 事实标准的无障碍规则引擎，Lighthouse 内核 |
| 2 | Playwright | Apache-2.0 | 多视口截图与溢出测量 |
| 3 | Lighthouse CI | Apache-2.0 | 性能 + 无障碍汇总 |

## 可借鉴做法（落到文件/组件级）

1. **横向溢出用 `scrollWidth > clientWidth` 判定，且要同时测 `documentElement` 与 `body`。**
   落到 `tools/check-overflow.mjs`：只测 `body` 会漏掉「html 溢出但 body 未溢出」的情况（`100vw` + 滚动条是最常见的成因）。

2. **弹层必须逐个打开后再扫描。**
   axe-core 只检查**当前已渲染**的 DOM，折叠的弹层内容不会被扫描。这与我方验收要求一致：10 个弹层要逐个 `click` 打开、扫描、关闭，而不是扫一次首页就算通过。
   落到 `tools/check-aplus-dialogs.mjs` 的用例表。

3. **自动化只能覆盖一部分，结论必须标注口径。**
   Deque 官方口径是自动规则平均覆盖约 57% 的 WCAG 问题。落到 README 的「已知边界」：本项目的可访问性结论只代表自动化检查通过 + 人工键盘走查，不代表整体无障碍合规。

## 不采纳及原因

- **axe-core / Playwright 不作为项目依赖引入**：两者都会显著增加 `node_modules` 体积与构建环境要求，而本次交付的验收是「本地一次性走查 + 截图留证」，不需要长期 CI。改为在本地用 Chrome 远程调试协议写零依赖脚本（与 232 既有 `tools/` 风格一致），并把 axe 的检查项人工对照执行。
- **Lighthouse CI**：需要 Chrome 启动参数与基线存储，当前仓库没有 CI 运行环境，登记为后续可选项。

## 结论

验收脚本零依赖、可重复执行，输出「通过/不通过 + 证据路径」；不通过项必须修代码，不允许调阈值放行。
